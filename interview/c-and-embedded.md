# C 与嵌入式基础：20 题

[返回目录](../README.md) · 难度：基础至进阶 · 建议每题口述 1–3 分钟。

## C01. 数组和指针有什么区别？

**参考回答：**数组是连续的同类型对象，指针对象保存一个地址。多数表达式中的数组名会转换为指向首元素的指针，但 `sizeof` 和一元 `&` 等场景不发生这种转换。`int a[10]` 的 `sizeof(a)` 是整个数组大小；函数参数中的 `int a[10]` 会调整为指针，不能用 `sizeof(a)` 求元素数量。

**追问：**`a + 1` 和 `&a + 1` 数值偏移是否相同？前者跨一个元素，后者跨整个数组。不要只说“数组名就是指针”。

## C02. `const int *p` 和 `int * const p` 分别限制什么？

**参考回答：**前者不能通过 `p` 修改所指的整数，但可改变 `p`；后者不能改变该指针的值，但可以通过它修改一个本来可写的整数。`const int * const p` 同时限制两者。`const` 修饰不承诺对象位于 ROM，也不使跨线程访问自动安全。

**误区：**把指向真正 `const` 对象的指针强转后写入会产生未定义行为，不能靠“编译通过”证明合法。

## C03. `static` 在函数内和文件作用域各有什么作用？

**参考回答：**函数内的静态对象具有静态存储期，跨调用保留值，作用域仍在对应块内；文件作用域的 `static` 函数或对象具有内部链接，只在当前翻译单元可见。普通文件作用域对象即使没写 `static` 也具有静态存储期。

**追问：**静态缓冲让函数不可重入怎么办？改为调用方提供缓冲、为每个实例保存上下文，或对共享状态同步。

## C04. `volatile` 能解决线程和中断共享变量的问题吗？

**参考回答：**不能把它当作完整同步机制。它约束对对象的访问优化，不保证 `counter++` 原子，不建立线程间的先后关系，也不自动保护多个字段的一致性。裸机寄存器应按平台规定访问；任务间共享状态应使用目标平台支持的原子、锁、队列或临界区，并分析中断与多核并发。

**误区：**在 Linux 内核直接用 `volatile` 指针代替 MMIO 访问接口也不可靠。参见 [Linux 5.4 对 volatile 的说明](https://www.kernel.org/doc/html/v5.4/process/volatile-considered-harmful.html)。

## C05. 栈、堆和静态存储区分别适合放什么？

**参考回答：**自动局部对象通常放在线程栈上，适合短生命周期的小对象；动态分配对象的生命周期由程序管理；静态存储期对象存活于整个程序执行期。标准 C 规定生命周期，不要求某个物理内存布局。嵌入式要结合链接脚本、任务栈大小、DMA 可访问区域和缓存属性安排内存。

**追问：**为什么不能返回局部数组地址？对象离开作用域后生命周期结束。也不能因为“地址看起来还没变”就继续访问。

## C06. `malloc` 后使用和释放要检查哪些边界？

**参考回答：**检查元素数与元素大小相乘是否超过 `SIZE_MAX`、分配是否失败、初始化是否完成、释放责任属于谁。每条错误路径都应释放已拥有的资源。释放后所有别名都失效，仅把一个指针置空不能修复其他悬空指针。

**追问：**如何安全调用 `realloc`？先把结果放到临时指针，成功后替换；明确零大小请求的策略，避免覆盖旧指针导致泄漏。

## C07. 为什么把网络字节数组强转为结构体可能出错？

**参考回答：**可能同时违反对齐要求、对象访问规则、协议字节序及结构体布局假设。编译器可能插入填充，打包属性也不能统一解决未对齐访问和端序。解析时先检查剩余长度，再按字节读取或复制到合适对象，并显式做端序转换。

**追问：**序列化时能直接 `send(fd, &obj, sizeof obj, ...)` 吗？需要协议明确定义布局；通常应逐字段编码，避免填充字节及平台差异。

## C08. 有符号与无符号运算有哪些常见陷阱？

**参考回答：**混合比较可能先转换类型，例如负整数与 `size_t` 比较未必按直觉进行。有符号整数溢出是未定义行为；无符号运算按模回绕，也仍可能造成长度校验绕过。应在运算前检查范围，不能先溢出再比较。

**例子：**检查拼接长度可用 `incoming > capacity - used`，但必须先保证 `used <= capacity`。不要无条件计算 `used + incoming`。

## C09. 位移和位掩码为什么常出问题？

**参考回答：**移位数不能为负，也不能大于等于提升后左操作数的位宽。位操作优先采用明确宽度的无符号类型，先验证字段偏移和宽度。构造全宽掩码时要单独处理，不能执行 `1u << 32` 来得到 32 位掩码。

**补充：**在本题采用的 C11 下，负数左移、非负有符号数左移后结果不能由其类型表示，均有未定义行为；负数右移是实现定义行为。`uint8_t`、`uint16_t` 运算前仍可能发生整数提升，不要只看变量声明就推断运算类型。

**追问：**寄存器读改写为何可能不安全？另一个执行者可能并发修改，且 W1C、只写、读清零寄存器不一定允许普通读改写，必须看芯片手册。

## C10. 宏和 `static inline` 函数如何选择？

**参考回答：**函数参数有类型，实参求值一次，更容易调试。宏适合条件编译或需要预处理的场景，但要完整加括号，避免多次求值。语句宏通常用 `do { ... } while (0)` 保持语法一致；这不能解决所有类型和副作用问题。

**例子：**`#define MAX(a,b) ((a)>(b)?(a):(b))` 不适合传入 `i++`。`inline` 也不保证最终一定内联。

## C11. 如何设计可靠的字符串接口？

**参考回答：**显式传入目标容量，说明输入是否必须以 NUL 结尾、是否允许重叠、截断时返回什么。容量大于零时尽量保证目标以 NUL 结束；零容量时不能写入。处理原始音频、网络包时应使用“地址 + 长度”，不要把二进制当成字符串。

**误区：**`strncpy` 不保证源长度达到限制时目标仍有终止符；`sizeof(pointer)` 不是所指缓冲容量。

## C12. 如何设计环形缓冲区？

**参考回答：**明确容量、读索引、写索引以及满空表示。可保留一个空槽，也可额外维护已用数量，但实际可用容量不同。读写处理跨尾部回绕，满时选择拒绝新数据、覆盖旧数据或丢整帧，并向调用方报告。

**追问：**单线程版本改成无锁 SPSC 是否只需加 `volatile`？不够，需要保证数据写入先于写索引发布，并满足平台原子性与内存序；多生产者又是另一组约束。

## E01. 中断里为什么要尽快返回？

**参考回答：**长时间处理会增加其他中断与任务的响应时间。中断中完成必要的状态读取、清中断和数据交接，将解析、网络通信、日志及界面工作移到适合的任务上下文。可否调用某 API 要看其是否可阻塞、是否支持 ISR 上下文。

**误区：**不能简单说“所有平台中断都不能调任何函数”。重点是执行上下文、栈、可重入性和 API 契约。

## E02. 互斥锁、信号量和队列有什么区别？

**参考回答：**互斥锁主要保护共享资源，通常有所有权；信号量表达事件或可用资源计数；队列传递数据并可表达缓冲与背压。选择时要考虑是否允许等待、优先级继承、ISR 接口及数据复制成本。不能把某个 RTOS 的实现细节推广成所有系统的结论。

**追问：**一个音频回调要把 PCM 交给播放任务，应如何明确数据所有权？说明队列里传副本还是指针，以及何时可复用原缓冲。

## E03. 优先级反转是什么？

**参考回答：**低优先级任务持有高优先级任务所需的锁，中优先级任务又抢占低优先级任务，导致高优先级任务间接受阻。可使用支持优先级继承的互斥锁、缩短临界区或重构资源访问。优先级继承有适用限制，不能代替避免死锁和合理调度。

**追问：**如果两任务反向获取两把锁，提升优先级能否修复？不能，应统一加锁顺序或改变设计。

## E04. UART、I2C、SPI 如何选？

**参考回答：**UART 通常异步点对点，适合日志及串行设备；I2C 使用地址与共享总线，常见于控制和低速传感器；SPI 通常同步、通过片选区分设备，常用于显示或高速外设。选择要结合速率、电平、距离、引脚数量、总线负载及外设协议。

**误区：**I2C 外设地址、7 位地址与包含读写位的地址字节要分清；SPI 四种模式由 CPOL/CPHA 组合决定，不能只看频率。

## E05. CPU 缓存为什么可能影响 DMA？

**参考回答：**CPU 的缓存副本与设备看到的内存内容可能不同。必须根据平台的 DMA 一致性模型和 API 处理映射、方向、同步及所有权切换；Linux 使用 DMA API，不随意用物理地址或手工缓存操作替代。`volatile` 不会自动清缓存。

**追问：**缓存行中的无关数据为何可能被影响？维护操作通常以缓存行为粒度，需要考虑对齐及是否共享缓存行。

## E06. 如何计算 PCM 码率和缓冲时长？

**参考回答：**字节率 = 采样率 × 通道数 × 每样本字节数。16 kHz、16 bit、单声道为 `16000 × 1 × 2 = 32000 B/s`；3200 字节表示 100 ms PCM。Base64 负载长度为 `4 × ceil(n/3)`，再叠加消息及网络开销。

**误区：**100 ms 是音频包覆盖的时间，不是端到端响应时间；端到端还包含排队、网络、云服务、播放等环节。

## E07. 看门狗应该在哪里喂？

**参考回答：**应反映关键任务和业务链路是否健康，而不是只证明一个高优先级定时器仍在运行。可由监控任务核对关键任务进度、超时及资源异常后决定是否喂狗。复位后保留原因和必要上下文，避免无限重启掩盖缺陷。

**追问：**网络断开是否一定触发复位？先定义可恢复的故障和恢复策略，不能把正常离线等同于系统死锁。

## E08. 如何说明“实时”和“性能优化”？

**参考回答：**先定义截止时间、负载、硬件、采样方式及最坏情况，再记录分布或上界。优化前后在可比条件下测试。平均值不能代表最坏情况，实机视频也不能单独证明长时间稳定性。

**项目练习：**分别列出语音首包、开始播放、完整播放三个时间点；没有仪表与记录时只描述方案，不虚构毫秒数。
