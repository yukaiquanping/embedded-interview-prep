通用约定：非空指针必须指向题目声明大小的有效对象；函数无法判断“地址看起来非空但已经释放”。调用者提供可读、可写区域并保证其生命周期。除 C01 明确支持重叠外，输入、输出和状态对象不应重叠。下列“错误时不修改输出”均建立在这些指针契约成立的前提上。

## C01：有边界的字符串拷贝（15 分）

实现：

```c
copy_result bounded_str_copy(char *dst, size_t capacity, const char *src,
                             size_t src_extent, size_t *source_length);
```

`src_extent` 是来源区域最多可读的字节数。先在这个范围内查找 `\0`，不能调用会无限扫描的 `strlen(src)`。`source_length` 可为空；非空时，成功找到终止符后写入源字符串长度，不含 `\0`。

返回值与行为：

| 返回值 | 条件与结果 |
| --- | --- |
| `COPY_OK` | 完整复制，并写入终止符 |
| `COPY_TRUNCATED` | 空间不足；`capacity > 0` 时复制前 `capacity - 1` 字节并以 `\0` 结尾 |
| `COPY_UNTERMINATED` | 前 `src_extent` 字节内没有终止符，目标与长度输出均保持原值 |
| `COPY_BAD_ARGUMENT` | `src == NULL`，或 `capacity > 0` 且 `dst == NULL`；输出保持原值 |

允许 `dst == NULL && capacity == 0`，此时只获取源长度，返回 `COPY_TRUNCATED`。即使源为空串，零容量也没有空间存终止符。仅来源 `src` 与目标 `dst` 可以重叠；非空的 `source_length` 必须指向独立的 `size_t` 对象，不得与来源或目标字节区域重叠。容量指向可写区域的真实大小。

示例：源为 `"hello"`、`src_extent = 6`、目标容量为 4，目标得到 `"hel"`，长度输出为 5，返回 `COPY_TRUNCATED`。源为三个字节 `{ 'a', 'b', 'c' }`、`src_extent = 3` 时，返回 `COPY_UNTERMINATED`，不会继续读第四字节。

参考思路：先有界扫描，完成扫描后再复制；使用 `memmove` 支持重叠。用 `length < capacity` 判断是否完整容纳，避免先计算 `length + 1` 的溢出问题。时间复杂度 `O(src_extent)` 上界，额外空间 `O(1)`。

评分：有界扫描及错误不写入 5 分；截断和终止符 4 分；零/一容量及可选长度输出 3 分；重叠与长度运算 3 分。

自测重点：空串、容量为 0/1/恰好足够、来源无终止符、无效参数、向前和向后重叠。

追问：为什么 `strncpy` 不能自动满足这个契约？答题时应指出：源长度达到拷贝上限时，它不保证目标以 `\0` 结束；不足上限时会补零。它也没有本题的来源可读范围和明确返回状态。

## C02：32 位大端编解码（10 分）

实现：

```c
bool read_be32(const uint8_t *src, size_t length, uint32_t *value);
bool write_be32(uint8_t *dst, size_t capacity, uint32_t value);
```

协议字节序为大端。读取和写入均只处理前 4 字节，多余字节保持原样。输入长度/容量小于 4，或必要指针为空，返回 `false`，不修改输出；成功返回 `true`。

示例：`{0x12, 0x34, 0x56, 0x78}` 应解码为 `0x12345678`，且不能依赖本机字节序或地址对齐。

参考思路：逐字节移位与组合。先将 `src[i]` 转成 `uint32_t` 再左移，避免默认整数提升后在有符号类型上左移溢出。不要把字节指针强转成 `uint32_t *` 直接解引用；这种做法还涉及对齐、别名及主机字节序。时间、额外空间均为 `O(1)`。

评分：大端结果正确 4 分；长度和空指针边界 3 分；无对齐/别名/有符号移位依赖 3 分。

自测重点：`0`、`UINT32_MAX`、已知字节序、非自然对齐的字节起始位置、长度 3/4、周围保护字节，以及多组往返编码。

## C03：单线程环形字节缓冲（20 分）

实现 `ring_init`、`ring_write`、`ring_read`，使用调用者提供的存储区域，不分配内存。

```c
bool ring_init(byte_ring *ring, uint8_t *storage, size_t capacity);
size_t ring_write(byte_ring *ring, const uint8_t *src, size_t length);
size_t ring_read(byte_ring *ring, uint8_t *dst, size_t capacity);
```

具体要求：

- 容量为 `N` 时，`N` 个字节全部可用，不预留一个空槽。可额外记录当前长度来区分空与满。
- 写入返回实际接受字节数：空间不足时只写可容纳部分，不覆盖未读数据。读出返回实际读取字节数。
- 允许零容量，此时存储指针可以为空；所有读写返回 0。容量大于零时，存储必须非空。
- 非零读写长度要求对应数据指针非空，否则返回 0 且不改变缓冲状态。零长度可传空指针。
- 仅支持同一线程按序调用，调用者不能直接修改已初始化状态字段。数据参数不得与环形存储重叠。

示例：容量 5，写入 `[1,2,3,4,5,6]` 返回 5；读出 3 字节得到 `[1,2,3]`；再写入 `[6,7,8]` 返回 3；最后读出得到 `[4,5,6,7,8]`。

参考思路：维护 `read_index` 和 `length`，写位置由二者推导；每处理一字节，索引到末尾就回到 0。避免在零容量上取模，也不要认为 `(index + length) % capacity` 的加法一定不会溢出。读写时间为实际处理字节数的 `O(k)`，除调用者提供的存储外额外空间 `O(1)`。

评分：FIFO 和部分读写 7 分；回绕、空满及全部容量可用 6 分；零容量和参数边界 4 分；索引运算及并发适用范围 3 分。

自测重点：零/一容量、写满后再写、读空、读写跨尾部、反复回绕。参考测试还用独立的线性 FIFO 模型对比伪随机读写结果。

追问：能直接把它用于中断生产者、线程消费者吗？不能把当前实现直接当作并发队列；需要重新定义共享字段所有权、内存可见性和同步方式。仅给字段加 `volatile` 不能完成这些保证。

## C04：流式分帧解析（25 分）

字节流协议定义为：

```text
MAGIC       LEN       PAYLOAD       CHECKSUM
1 byte      1 byte    LEN bytes     1 byte
0xA5        0..32                  LEN XOR 每一个 PAYLOAD 字节
```

校验不含 `MAGIC`。允许长度为 0，其校验字节为 0。`0xA5` 可以出现在负载中，不需要转义。实现持久状态解析器：

```c
void parser_init(frame_parser *parser);
size_t parser_feed(frame_parser *parser, const uint8_t *bytes, size_t length,
                   frame_callback callback, void *ctx);
```

解析规则：

- 使用前调用 `parser_init`。每次输入可是一帧的一部分、多帧，或包含噪声；未收齐的帧保留在状态中。
- 在等待帧头时丢弃非 `0xA5` 字节。收到非法长度（大于 32）或错误校验后，丢弃已经消费的内容，从**下一字节**重新寻找帧头；该错误字节不再次作为新帧头处理。
- 成功一帧就同步调用一次回调，按接收顺序传递负载及长度。返回本次成功帧数。回调可为空，此时只计数。
- 回调得到的是解析器内部缓冲的临时视图；若需保留，应在回调返回前复制。禁止在回调中重入同一个解析器，输入数据也不能与解析器对象重叠。
- `parser == NULL`，或非零输入长度下 `bytes == NULL`，返回 0；后者不改变有效解析器的状态。零输入长度不清空未完成的帧。`parser_init(NULL)` 无操作。

示例：帧 `A5 03 11 A5 22 95` 的负载是 `11 A5 22`，校验为 `03 XOR 11 XOR A5 XOR 22 = 95`。分成 `A5 03 11` 和 `A5 22 95` 两次输入，只应在第二次调用中交付一帧。

参考思路：四态机 `等待帧头 → 等待长度 → 接收负载 → 等待校验`。零长度跳过负载态；解析器只保存最多 32 字节负载。处理 `n` 个输入字节时间 `O(n)`，固定缓冲使额外空间为 `O(1)`。

评分：状态跨调用保留、半帧与粘连帧 8 分；长度界限及校验 6 分；空负载、负载含帧头与噪声 4 分；回调生命周期和输入契约 4 分；错误恢复规则 3 分。

自测重点：每一个二段切分位置、逐字节输入、一次多帧、空负载、最大负载、非法长度、校验错后紧跟有效帧、最后一个校验字节尚未到达。另检查错误长度或校验字节恰为 `0xA5` 时不会复用该字节，并验证下一次输入正常帧后可以恢复交付。

协议边界：XOR 只用于练习，不是可靠检错或鉴权方案。被破坏但仍小于等于 32 的长度可能吞掉后续帧头；本协议不保证从任意错误位置立即恢复。实际串口/网络协议可按需求增加可靠同步标识、CRC、超时和序列号，这些不算本题已实现功能。

## C05：有序数组的 lower_bound（15 分）

实现：

```c
bool sorted_lower_bound(const int32_t *array, size_t count, int32_t target,
                        size_t *index, bool *found);
```

输入已按非递减顺序排列；函数不额外扫描验证排序。输出 `index` 为首个 `array[index] >= target` 的位置；若所有元素都小于目标，返回位置 `count`。`found` 表示该位置是否正好等于目标。因此含重复值时，应给出第一次出现的位置。

空数组允许 `array == NULL && count == 0`，结果为 `index = 0, found = false`，函数返回 `true`。非空数组指针为空，或任一输出指针为空，返回 `false`，不修改输出。输出位置等于 `count` 时，不能再用它解引用数组。

示例：数组 `[-3,0,0,0,7]`，查找 0 得到 `(1,true)`；查找 1 得到 `(4,false)`；查找 9 得到 `(5,false)`。

参考思路：在半开区间 `[left,right)` 上二分，`mid = left + (right-left)/2`；若 `array[mid] < target` 就排除左半边，否则保留左半边。循环结束时区间收敛到插入位置。时间 `O(log n)`，额外空间 `O(1)`。

评分：首个位置与重复值 6 分；空数组和缺失目标 4 分；区间不变式及中点计算 3 分；错误参数语义 2 分。

自测重点：空数组、最小/最大 32 位整数、重复值、目标落在两值之间、目标大于全部元素、与线性查找对比。

## C06：位字段提取与替换（15 分）

实现：

```c
bool field_get_u32(uint32_t word, unsigned int offset, unsigned int width,
                   uint32_t *value);
bool field_set_u32(uint32_t word, unsigned int offset, unsigned int width,
                   uint32_t value, uint32_t *updated);
```

位号从最低位 0 开始。合法范围：`offset < 32`、`width >= 1`、`width <= 32 - offset`。提取的结果右对齐。替换时，`value` 必须能由 `width` 位表示，否则返回 `false`，不能静默截断。成功替换必须保留字段以外的所有位。

任何非法范围或必要输出指针为空，返回 `false`，输出保持原值。必须支持 `offset = 0, width = 32`，不允许产生左/右移 32 位。

示例：`word = 0xA5`，`offset = 4, width = 4`，提取得 10；替换为 3 得 `0x35`。宽度为 3 时，写入 8 应拒绝。

参考思路：宽度为 32 时掩码直接取 `UINT32_MAX`，其余情况才计算 `(UINT32_C(1) << width) - 1`。验证范围后，以移位和掩码完成操作。时间和额外空间均为 `O(1)`。

评分：正确掩码、提取与保留其他位 6 分；全宽 32 和最高位 4 分；非法范围及值超宽检查 3 分；无移位未定义行为 2 分。

自测重点：最低/最高一位、全 32 位、宽度为零、越界、超宽值；参考测试遍历全部合法偏移与宽度组合，检查替换后目标字段与其余位。

追问：能把这一段直接用于 MMIO 寄存器读改写吗？整数运算示例不处理总线访问、并发、W1C（写 1 清零）等硬件语义。驱动代码需根据寄存器手册选择访问与同步方式。
